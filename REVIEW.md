# REVIEW.md

Defects found in the starter `app/main.py`, and how each was fixed.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Grace check is done on whole minutes (`> 10`), so 09:40:01 gives 0 instead of 10 (R2 says *strictly more than 10:00*). | Shift 09:30, punch-in 09:40:01 -> expected 10, got 0. | Compare in seconds (`> 600`), then floor to minutes. |
| 2 | `compute_late_minutes` | `punch_in.replace(hour=h, minute=m)` takes the shift start on the punch-in's own (UTC/naive) date and zone, not IST. A 09:35 IST punch is 04:05 UTC, so it is compared with 09:30 UTC. | Any normal punch-in gets wrong late minutes (huge negative -> 0, or hours late). | Convert to IST, build the shift start from the attendance date in IST. |
| 3 | `compute_late_minutes` / `punch_in` | Overnight shifts ignored: no R1 rule, so a 02:00 punch for a 22:00-06:00 shift gets the wrong date and wrong lateness. | Employee with 22:00-06:00 shift punching in at 21:55 or after midnight. | `attendance_date()` implements R1; lateness is measured from that date's shift start. |
| 4 | `compute_work_hours` | Python `round()` on a float can disagree with the required decimal half-up rounding. | 54 seconds is 0.015 h: the starter returns 0.01, but R4 requires 0.02. | `Decimal(seconds)/3600` quantized with `ROUND_HALF_UP`. |
| 5 | `compute_overtime` | No 30-minute minimum (R3); ignores overnight (shift end is next day); builds `end` from a date string with seconds left over and mixes naive/aware datetimes (`TypeError` against a naive `punch_out`). | Punch-out 5 minutes after shift end returns 5, should be 0. | New `overtime_minutes_for`: floor minutes, only if >= 30, overnight-aware, all datetimes aware. |
| 6 | `compute_*` / `half_day` | `half_day` is never computed at all (R5), and nothing computes it after punch-out. | Sample 4 (3.5 h) would be stored `half_day: false`. | `derived_fields()` computes it from the *rounded* work_hours (< 4.50). |
| 7 | `punch_in` | Unknown employee -> `emp` is `None` -> `TypeError` -> **500**. | POST with an emp_code that does not exist. | `get_employee_or_404`. |
| 8 | `punch_in` | `find_one` then `insert_one` is a race: two parallel requests both see "nothing" and both insert. | Fire 10 identical requests in parallel; several 201s. | Unique index on `(emp_code, date)`; insert inside `try/except DuplicateKeyError` -> 409. |
| 9 | `punch_in` | `datetime.fromtimestamp(ms / 1000)` uses the *server's local time zone*, keeps milliseconds, accepts anything (seconds, negative, 0 is falsy so ignored). | `punched_at` in seconds silently becomes 1970. Result changes with server TZ. | Strict `EpochMs` type (>= 1e11, int only) -> 422; `ms_to_dt` is UTC and truncated to the second (R1). |
| 10 | `punch_in` | `status: str` accepts anything (`"ABSENT"`, `"foo"`). | POST `status: "foo"` is stored. | `Literal["PRESENT","WFH","ON_DUTY"]` -> 422. |
| 11 | `punch_in`, `list_attendance` | Responses leak an `id` (the Mongo `_id` as a string) and return raw datetimes (ISO strings) instead of epoch ms; legacy documents lack `history`/`half_day`. | Response has `id`; `punch_in` is a string. | `record_out()` whitelists fields, converts instants to ms, defaults missing fields. |
| 12 | `create_employee` | `find_one` then insert: race on duplicates (needs a unique index); `datetime.now()` is local naive time; no validation (emp_code format, shift pattern, `shift_start == shift_end`, real `joined_on` date, email); `created_at` returned as datetime not ms. | Parallel duplicate creates; `emp_code: "x"`; `shift_start: "25:99"`. | Unique index + `DuplicateKeyError` -> 409; Pydantic constraints; UTC time; `employee_out()`. |
| 13 | `list_employees` | `skip = page * page_size` skips the whole first page (should be `(page-1)*page_size`); `total` counts all employees ignoring the filter; no sort so pages are unstable; `page`/`page_size` unvalidated (0, -1, 10000). | `GET /employees?page=1` returns page 2's rows. | Correct skip, `count_documents(q)`, sort by `emp_code`, `ge=1`, `le=100`. |
| 14 | `list_attendance` | Loads the *entire* matching collection into memory and sorts/slices in Python; no index; sort only by date (ties unstable); `total` from `len`; `page=0` gives negative slice; dates/status not validated; `date_from > date_to` not rejected. | 100k docs: slow and memory-heavy. | `find().sort().skip().limit()` backed by indexes; sort `date desc, emp_code asc`; 422 on bad inputs. |
| 15 | `health` | Always returns ok, even when MongoDB is down. | Stop MongoDB, call `/health`. | Pings MongoDB; 503 on failure. |
| 16 | module level | Naive datetimes from PyMongo (`tz_aware` off), no server selection timeout, no indexes created at startup. | Timestamps compared to aware ones raise `TypeError`; slow queries. | `tz_aware=True`, 5 s timeout, `ensure_indexes()` at startup (and retried from `/health`). |
| 17 | missing endpoints | `punch-out`, PATCH, analytics and explain not implemented. | 404 on all of them. | Implemented (see `app/main.py`). |
| 18 | `build_department_summary` | `$lookup` produces an array containing the per-employee aggregate, but the department `$group` attempted to sum those arrays as scalar fields. This makes the totals wrong or unusable. | Run the monthly department summary with an employee who has attendance logs. | `$unwind` the zero-or-one result with `preserveNullAndEmptyArrays: true` before grouping, then sum the scalar fields. Added a regression test for stage order and scalar accumulation. |

## Looked at and decided it was fine
* `load_dotenv()` does not override variables already in the environment, so real env vars win, as required.
* Endpoints are plain `def`, so FastAPI runs them in a thread pool; blocking PyMongo calls do not block the event loop.
* Dropping `_id` with `doc.pop("_id")` in `create_employee` is right in intent; I replaced it by a field whitelist because it is safer.
